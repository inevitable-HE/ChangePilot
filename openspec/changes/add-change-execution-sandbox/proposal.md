## Why

ChangePilot 需要一个可复现且不依赖生产系统的执行环境，才能证明 Agent 生成的计划不仅可读，还能在真实约束下安全完成数据库与服务协同变更。该环境也为故障注入、补偿回滚和断点恢复提供稳定的面试演示与自动化测试基线。

## What Changes

- 提供一个可重置的订单服务 V1/V2 示例系统及其本地数据库状态。
- 提供受控工具，用于检查环境、执行 Schema 迁移、切换服务版本、运行健康检查和业务冒烟测试。
- 为所有变更工具声明输入输出、风险级别、幂等键和可用补偿动作，使其可由可靠工作流运行时统一调度。
- 支持健康检查失败、工具超时和进程中断等故障注入，并验证自动回滚或恢复执行。
- 默认使用本机 Python 与 SQLite 运行；保留 PostgreSQL/Docker 适配边界，但不将其作为 V1 前置条件。
- 明确沙箱仅面向本地演示与测试，不提供生产环境连接能力。

## Capabilities

### New Capabilities

- `change-execution-tools`: 定义数据库迁移、服务部署、环境检查、验证和补偿回滚等受控执行工具的行为契约。
- `change-sandbox-scenario`: 定义订单服务 V1 到 V2 的可重置演示场景、故障注入和端到端恢复验收行为。

### Modified Capabilities

无。

## Impact

- 新增本地订单服务、数据库 Fixture、迁移脚本和故障注入配置。
- 新增与可靠工作流运行时对接的工具适配层。
- 新增端到端测试，覆盖成功升级、验证失败回滚和进程中断恢复。
- V1 不要求 Docker、WSL 或外部数据库服务；后续可通过相同工具契约增加 PostgreSQL 适配器。
