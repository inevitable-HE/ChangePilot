## ADDED Requirements

### Requirement: 受控工具注册
系统 MUST 仅允许工作流调用已注册的变更工具，并为每个工具声明版本、输入输出 Schema、风险级别、超时、幂等规则和补偿能力。

#### Scenario: 拒绝未注册工具
- **WHEN** 执行计划引用未注册的工具名称或版本
- **THEN** 系统拒绝启动该步骤，并记录不包含实际副作用的审计事件

#### Scenario: 校验工具输入
- **WHEN** 工具调用参数不符合该工具的输入 Schema
- **THEN** 系统在调用工具前返回结构化校验错误

### Requirement: 环境状态检查
系统 SHALL 提供只读检查工具，返回当前服务版本、Schema 版本、迁移账本状态和沙箱身份。

#### Scenario: 获取一致的环境快照
- **WHEN** 工作流在执行或恢复前调用环境检查工具
- **THEN** 工具返回可用于前置条件校验和审计的结构化环境快照

### Requirement: 幂等 Schema 迁移
系统 SHALL 通过迁移账本执行版本化 Schema 迁移，并 MUST 在修改数据库前验证当前版本和迁移前置条件。

#### Scenario: 首次执行升级迁移
- **WHEN** 当前数据库处于 V1 且请求执行 V1 到 V2 迁移
- **THEN** 工具完成迁移、更新迁移账本并返回 V2 数据库指纹

#### Scenario: 重复执行已完成迁移
- **WHEN** 相同幂等键对应的 V1 到 V2 迁移已经成功
- **THEN** 工具返回已完成结果且不再次修改 Schema 或业务数据

#### Scenario: 迁移前置条件不满足
- **WHEN** 当前 Schema 版本或数据库指纹与迁移声明不一致
- **THEN** 工具拒绝执行并返回需要人工处理的结构化错误

### Requirement: 服务版本切换
系统 SHALL 提供部署工具，将订单服务在已知版本之间切换，并在切换前验证目标版本与数据库兼容性。

#### Scenario: 切换到 V2 服务
- **WHEN** 数据库满足 V2 前置条件且工作流请求部署 V2
- **THEN** 工具以幂等方式将活动服务版本设置为 V2并返回版本证据

#### Scenario: 拒绝不兼容部署
- **WHEN** 数据库仍处于 V1 且请求部署只兼容 V2 Schema 的服务版本
- **THEN** 工具拒绝版本切换并保持原活动版本

### Requirement: 健康检查与业务验证
系统 SHALL 分别提供服务健康检查和订单业务冒烟测试工具，并返回机器可判定的验证证据。

#### Scenario: V2 验证成功
- **WHEN** V2 服务和数据库状态正确且未启用故障注入
- **THEN** 健康检查与业务冒烟测试均返回成功，并包含服务和 Schema 版本

#### Scenario: 健康检查失败
- **WHEN** 故障配置要求 V2 健康检查失败
- **THEN** 工具返回失败证据且不得自行绕过或修改故障结果

### Requirement: 策略约束的补偿
系统 SHALL 为可补偿工具提供显式补偿动作，并 MUST 在执行逆向数据库迁移前检查可逆性和数据安全前置条件。

#### Scenario: 回退服务版本
- **WHEN** V2 验证失败且补偿策略要求回退部署
- **THEN** 部署补偿工具将活动服务恢复为兼容的先前版本并记录前后状态

#### Scenario: 拒绝不安全的逆向迁移
- **WHEN** 数据库包含逆向迁移会破坏的数据或迁移声明为不可逆
- **THEN** 迁移补偿工具不修改数据库，并返回需要人工处理的状态和原因

### Requirement: 沙箱资源边界
变更工具 MUST 仅访问当前沙箱运行目录和已注册资源，不得接受任意生产地址、绝对路径、Shell 命令或无限制 SQL。

#### Scenario: 拒绝目录越界
- **WHEN** 工具参数解析后的路径位于当前沙箱目录之外
- **THEN** 工具拒绝调用并记录安全审计事件
