## ADDED Requirements

### Requirement: 变更请求提交
控制台 SHALL 允许操作者提交结构化变更请求，并展示请求是否进入信息澄清、计划待审阅或拒绝状态。

#### Scenario: 提交完整请求
- **WHEN** 操作者提交包含目标系统、期望状态和约束的完整变更请求
- **THEN** 系统创建可追踪的请求并进入计划生成流程

#### Scenario: 请求需要补充信息
- **WHEN** 规划 Agent 判定安全规划所需的信息缺失
- **THEN** 控制台展示具体澄清问题，且不得启动执行运行

### Requirement: 计划审阅
控制台 SHALL 展示结构化计划的版本、步骤依赖、风险级别、审批点、验证动作、补偿动作和知识证据。

#### Scenario: 审阅高风险步骤
- **WHEN** 操作者打开包含高风险数据库迁移的计划
- **THEN** 控制台在同一计划上下文中展示该步骤的风险依据、引用来源和补偿策略

#### Scenario: 计划校验失败
- **WHEN** 计划未通过确定性安全校验
- **THEN** 控制台展示违规原因且不提供启动执行操作

### Requirement: 人工审批
控制台 SHALL 允许操作者批准或拒绝等待审批的步骤，并 MUST 由后端校验审批版本、运行状态和审批权限上下文。

#### Scenario: 批准当前步骤
- **WHEN** 操作者批准当前计划版本中处于等待状态的风险步骤
- **THEN** 后端持久化审批证据并允许工作流继续执行该步骤

#### Scenario: 拒绝过期审批
- **WHEN** 操作者提交的审批对应旧计划版本或步骤已离开等待状态
- **THEN** 后端拒绝该审批，控制台刷新并展示最新状态

#### Scenario: 操作者拒绝步骤
- **WHEN** 操作者拒绝等待审批的风险步骤并填写原因
- **THEN** 工作流不执行该步骤，并按策略终止或进入补偿流程

### Requirement: 实时运行监控
控制台 SHALL 展示运行最终状态、步骤依赖和每个步骤的等待、运行、成功、失败、补偿或人工处理状态。

#### Scenario: 接收增量事件
- **WHEN** 运行产生新的步骤或审计事件
- **THEN** 已连接的控制台按服务端事件序号更新对应视图

#### Scenario: 断线后恢复
- **WHEN** 控制台断线后携带最后事件序号重新连接
- **THEN** 后端补发缺失事件，客户端最终状态与服务端快照一致

### Requirement: 失败处置与恢复
控制台 SHALL 展示失败原因、已执行副作用、补偿结果和可用的恢复命令，并 MUST 禁止不符合当前状态的操作。

#### Scenario: 展示已补偿失败
- **WHEN** 健康检查失败并完成允许的补偿
- **THEN** 控制台展示原失败步骤、每个补偿动作和恢复后的环境状态

#### Scenario: 展示人工处理状态
- **WHEN** 系统无法安全自动补偿或恢复
- **THEN** 控制台展示阻塞原因和只读诊断证据，不提供绕过安全检查的继续按钮

### Requirement: 审计查询与导出
控制台 SHALL 提供按运行查询的有序审计时间线，并允许导出由后端生成的 Markdown 和 JSON 报告。

#### Scenario: 导出完整运行报告
- **WHEN** 操作者导出一个已结束运行
- **THEN** 报告包含请求、计划版本、引用、审批、步骤、工具证据、补偿、模型用量和最终状态

#### Scenario: 脱敏敏感字段
- **WHEN** 审计事件或工具结果包含被标记为敏感的字段
- **THEN** 控制台和导出报告均显示脱敏值，且模型 API 凭据从不进入报告

### Requirement: 服务端状态权威
控制台 MUST 通过后端命令 API 改变运行状态，不得直接修改持久化记录、伪造审计事件或调用任意工具。

#### Scenario: 拒绝非法状态转换
- **WHEN** 客户端请求当前运行状态不允许的命令
- **THEN** 后端拒绝命令并返回最新权威状态
