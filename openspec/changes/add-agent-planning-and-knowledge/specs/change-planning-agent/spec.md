## ADDED Requirements

### Requirement: 模型提供方必须可替换且可模拟
系统 MUST 通过统一模型网关调用模型，并提供 DeepSeek 适配器与无需网络的 Mock LLM。业务规划逻辑不得直接依赖提供方 SDK 类型。

#### Scenario: 使用 Mock LLM 运行测试
- **WHEN** 测试配置选择 Mock LLM 并提供预设响应
- **THEN** 规划流程在不访问外部网络和不消耗 API 额度的情况下完成

#### Scenario: DeepSeek 暂时不可用
- **WHEN** DeepSeek 调用超时或返回可重试错误
- **THEN** 模型网关按照有限重试策略处理，并向调用方返回结构化失败而非无限循环

### Requirement: 关键上下文缺失时必须请求澄清
系统 MUST 在生成可执行计划前检查服务标识、当前与目标版本、变更内容和成功条件等关键字段。缺失信息不得由模型静默猜测。

#### Scenario: 目标版本缺失
- **WHEN** 用户只要求升级订单服务但未提供目标版本
- **THEN** 系统返回指向目标版本的结构化澄清问题，且不创建可执行计划

#### Scenario: 用户补充缺失信息
- **WHEN** 用户回答全部阻塞性澄清问题
- **THEN** 系统基于补充内容创建新的规划版本并保留先前澄清记录

### Requirement: Agent 必须生成版本化结构化计划
系统 SHALL 生成符合计划 Schema 的目标、假设、步骤、依赖、工具参数、风险、审批要求、成功条件、补偿意图和证据引用，并为计划保存版本与内容摘要。

#### Scenario: 生成服务和数据库联合变更计划
- **WHEN** 用户目标与知识上下文完整
- **THEN** Agent 返回包含数据库迁移、服务切换和验证依赖关系的结构化计划

#### Scenario: 模型返回非结构化内容
- **WHEN** 模型响应无法通过计划 Schema 校验
- **THEN** 系统最多执行配置允许的格式修复次数，仍失败时返回规划失败且不提交工作流

### Requirement: 计划提交前必须经过确定性安全校验
系统 MUST 在计划进入可靠工作流内核前重新验证任务图、工具白名单、参数 Schema、风险等级、审批要求和证据引用。模型不得降低确定性策略给出的风险等级。

#### Scenario: 模型将数据库写入标记为低风险
- **WHEN** 计划包含数据库写入工具但模型未要求审批
- **THEN** 确定性策略将步骤提升到配置风险等级并要求审批

#### Scenario: 计划引用未知工具
- **WHEN** 模型生成的步骤引用未注册工具
- **THEN** 系统拒绝计划并返回可定位到该步骤的校验错误

### Requirement: 规划过程必须携带可审计证据
系统 SHALL 为每个需要领域知识支撑的计划步骤记录证据引用；缺少必要证据时必须标记假设或请求用户确认。

#### Scenario: 迁移步骤有规范依据
- **WHEN** 数据库迁移步骤引用有效 Runbook 片段
- **THEN** 计划保存对应文档版本和片段位置，并可由用户查看

#### Scenario: 无法找到回滚规范
- **WHEN** 变更涉及高风险操作但未检索到回滚要求
- **THEN** 系统将其标记为阻塞性风险并要求补充信息，不直接产生可执行计划

### Requirement: 模型调用必须受预算和观测约束
系统 MUST 对单次规划的调用次数、token 和费用设置可配置上限，并记录模型、延迟、使用量、缓存命中和估算费用。API 密钥不得出现在记录中。

#### Scenario: 规划达到预算上限
- **WHEN** 当前规划累计估算费用或调用次数达到配置上限
- **THEN** 系统停止后续模型调用并返回预算耗尽状态

#### Scenario: 相同输入命中有效缓存
- **WHEN** 用户请求、模型配置和知识版本与已缓存规划输入一致
- **THEN** 系统复用缓存结果并记录缓存命中，不产生新的模型费用
