## Context

规划模块已经能完成请求规范化、知识检索、结构化生成、确定性校验与工作流映射；运营模块此前直接加载固定定义。集成必须保留“模型只提议、确定性代码授权、运行时执行”的权限边界。

## Decisions

1. `OperationsService` 对完整请求调用规划组合服务，仅接受 `PlanReady` 结果进入执行。
2. 默认模型根据受支持的演示目标生成确定性结构化响应，但仍经过真实 RAG、LangGraph、校验器和映射器。
3. `CHANGEPILOT_PLANNER_MODE=deepseek` 仅替换模型网关。
4. 规划轨迹为只读解释信息；执行审计仍是副作用的权威记录。
5. 就绪度检查只绑定三个只读工具，不产生审批、迁移、部署或补偿。

## Risks

- 离线模型可能被误认为固定工作流：通过第二类目标、不同计划及文档边界降低误解。
- 规划轨迹泄露敏感内容：V1 只索引仓库内示例手册，生产化仍需脱敏与访问控制。
- 模型输出绕过安全控制：所有输出必须通过严格 Schema、工具策略和工作流定义校验。
