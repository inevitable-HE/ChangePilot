# 架构总览

ChangePilot 将不确定的 Agent 规划与确定性的变更执行分离。模型负责理解意图、结合知识
提出候选计划；系统代码负责权限、依赖、审批、状态转换、恢复和审计。

## 分层职责

| 层次 | 主要职责 | 对应文档 |
| --- | --- | --- |
| Agent 规划与知识层 | Runbook 摄取、混合检索、模型规划、计划修复与证据绑定 | [Agent 规划与知识检索](agent-planning-and-knowledge.md) |
| 可靠工作流内核 | 状态机、任务图调度、审批屏障、事务、幂等、补偿与恢复 | [可靠工作流内核](reliable-workflow-core.md) |
| 受限执行层 | 在白名单工具和本地沙箱中执行发布、迁移与健康检查 | [本地执行沙箱](change-execution-sandbox.md) |
| 运营与评测层 | 面向操作者展示计划、审批、执行证据，并离线评估 Agent 闭环 | [运营控制台与评测](operations-console-and-evaluation.md) |

## 一次变更如何流动

```text
自然语言意图
  -> 知识检索与证据绑定
  -> 模型生成候选任务图
  -> 确定性规则校验
  -> 人工审批高风险步骤
  -> 可靠工作流调度
  -> 受限工具执行
  -> 验证 / 补偿 / 恢复
  -> 审计与评测
```

## 关键设计原则

- **模型不持有执行权**：模型输出只能成为候选计划，执行必须经过系统规则和工具边界。
- **证据可追溯**：每个计划保存检索证据、知识版本和模型调用信息。
- **状态可恢复**：运行、步骤、执行尝试和审批均持久化，进程重启后能够判断下一步。
- **副作用受约束**：工具采用结构化参数、白名单注册和稳定幂等键。
- **失败可解释**：原始失败、重试、补偿和恢复结果均保留在审计链中。
