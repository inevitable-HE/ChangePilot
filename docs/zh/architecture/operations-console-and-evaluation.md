# 运营控制台与评测

## 目标

第四阶段将规划和执行运行时组织为面向操作者的完整闭环：

```text
结构化请求
  -> 计划与证据审阅
  -> 确定性审批门禁
  -> 实时执行与审计事件
  -> 补偿或显式恢复
  -> 终态报告
  -> 可重复的安全评测
```

控制台不会直接执行工具，也不会直接修改工作流持久化。FastAPI 是权威命令边界，
React 应用只是查询与命令客户端。

## 操作 API

`OperationsService` 负责请求校验、固定演示计划构建、沙箱运行时装配、命令校验、
报告生成和脱敏。API 提供：

- 结构化请求提交和请求历史；
- 运行列表、快照、计划注解和基于游标的事件；
- 根据当前阶段、下一动作、变更上下文和活动安全控制生成的权威运行指引；
- 与版本绑定的批准或拒绝；
- 与运行修订版本绑定的恢复；
- SSE 审计事件推送，并允许客户端降级为轮询；
- 服务端生成的 JSON 与 Markdown 报告；
- 只读的版本化评测历史。

API 接收场景标识符，不接受任意 SQL、Shell 命令、文件系统路径或工具参数。审批命令
携带当前审批版本和绑定摘要，恢复命令携带当前运行修订版本。过期或非法命令返回冲突，
不会改变权威状态。

## 控制台

运营工作区承担三项职责：

1. 选择或提交一个隔离的变更运行。
2. 在批准副作用前审阅 DAG、依赖、风险、验证意图、证据和补偿。
3. 跟踪有序审计事件、检查载荷、恢复未知结果并导出终态报告。

控制台从最新已观察序号之后消费 SSE 事件，并定期与完整服务端快照校准。因此，事件
推送用于提升响应速度，但不作为事实来源。操作者指引遵循相同原则：API 根据权威快照
推导指引，控制台只负责翻译和展示。

## 评测

核心评测数据集独立于代码进行版本管理，并记录提示词、知识、指标、随机种子、开发集
和保留集。离线运行器使用确定性 Mock 计划，但会经过真实的本地工作流与沙箱边界。
评测指标包括：

- 计划有效性、必需与禁止动作、风险和证据；
- 审批阻断、幂等、补偿、恢复和完成状态；
- 延迟、调用次数、Token、缓存命中和预估费用。

`examples/evaluations/baseline-v1/evaluation.json` 是首个提交且通过的基线。
结果页面展示聚合安全指标、样例级失败、预算遥测、回归和兼容基线差异。

## 在线成本边界

只有显式设置 `CHANGEPILOT_RUN_ONLINE_EVAL=1` 且提供 DeepSeek Key 时，在线评测
才会启用。在线运行器在每次调用前要求用量估算，并在请求模型前预留样例、调用次数、
Token 和预估费用预算。任何一次预留将超过限制时，剩余样例会被跳过；部分完成结果
会记录已完成样例、跳过样例、用量和停止原因。凭据只用于构造模型请求，不会写入评测
或运营报告。

## 本地演示

按照 README 启动 API 和控制台，然后：

1. 创建一个成功的订单服务升级。
2. 打开 `migrate-schema`，审阅其 Runbook 引用和回滚工具。
3. 批准待处理的 Schema 迁移，观察运行进入 `succeeded`。
4. 创建健康检查失败场景，观察逆序补偿。
5. 创建重启恢复场景，核对已提交迁移且不重复执行。
6. 打开评测页面，查看离线基线和零在线费用遥测。

该本地实现证明的是控制平面语义。生产使用仍需要组织级身份、授权、密钥管理、分布式
协调、部署适配器、数据库备份策略、可观测性和保留策略。
