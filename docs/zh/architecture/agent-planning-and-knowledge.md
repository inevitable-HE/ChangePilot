# Agent 规划与知识检索架构

## 范围

第二阶段在第一阶段的可靠工作流运行时之前增加一个受约束的规划 Agent。它的职责
在生成并持久化经过校验的 `PreparedWorkflow` 后结束，绝不会直接执行变更工具。

完整闭环如下：

1. 规范化结构化变更请求。
2. 请求补充缺失的必要上下文。
3. 检索版本化 Runbook 证据。
4. 请求模型生成结构化变更计划。
5. 使用确定性代码校验工具、参数、依赖、证据、风险、审批和补偿。
6. 模型输出格式错误时最多修复一次，否则返回终态结果。
7. 将已接受计划绑定到知识快照，并转换为运行时工作流。
8. 由可靠运行时执行工具、等待审批、在中断后恢复、补偿失败副作用并记录审计链。

RAG 提供证据，LangGraph 表达有限的规划状态。Agent 能力来自完整反馈闭环及其
权限边界，而不是由某个框架本身定义。

## 规划图

```text
normalize
   |
required context --missing--> clarification_required
   |
retrieve --conflict--> clarification_required
   |
generate --budget--> budget_exhausted
   |        \--provider failure--> planning_rejected
validate --policy violation--> planning_rejected
   |
malformed --one repair--> validate
   |
plan_ready -> prepare_workflow -> Phase 1 runtime
```

每个分支都有有限终态，不存在无限模型循环、模型自主递归或由模型控制的工具执行。

## 模块边界

- `planning.domain` 负责请求、证据、计划、终态结果、知识元数据和工具策略等
  严格 Pydantic 契约。
- `planning.ports` 定义模型、知识、缓存、用量和规划持久化契约。
- `planning.application` 负责摄取、检索融合、图节点、校验、工作流映射和编排服务。
- `planning.adapters` 提供 DeepSeek 与 Mock 模型网关、SQLite 知识与规划持久化、
  FTS5 检索和可选本地 BGE Embedding。
- `workflow` 是唯一允许执行工具并修改外部状态的模块。

交接使用已有的 `WorkflowDefinition.from_mapping()` 边界，因此模型输出无法绕过
第一阶段的工作流定义校验。

## 知识与证据

Runbook 包含稳定文档 ID、不可变版本、来源、信任等级、策略键、生效日期、生命周期
状态和规则摘要。Markdown 标题驱动确定性分块。SQLite 保存文档版本、分块和 FTS5
trigram 索引。启用可选 BGE 适配器时，向量排名与关键词排名通过倒数排名融合合并。

每个计划步骤引用精确证据，引用中包含文档与版本、分块 ID、位置和内容摘要。多个
活动策略版本冲突时，系统会要求澄清，而不是静默选择。知识快照摘要把计划与完整索引
状态绑定；知识发生变化后，已经生成的计划会被判定为过期。

## 模型边界与成本控制

`DeepSeekModelGateway` 只负责转换类型化的模型请求与响应。
`BudgetedModelGateway` 在其外部提供确定性缓存、有限重试、用量记录、最大调用次数、
累计 Token 上限和可选预估费用上限。提示词、策略、模型、工具和知识版本共同构成
可复现边界。

生产配置应通过 SQLite 适配器持久化缓存和用量记录。默认测试使用
`MockModelGateway`；真实 DeepSeek 测试必须显式开启，且最多发起一次小额请求。

## 安全与权限

检索文本作为用户证据载荷进行序列化，系统提示始终将它描述为不可信数据。Runbook
中的指令不能改变模型角色、请求密钥、绕过审批或调用工具。

模型可以提出风险等级，但不能降低工具注册描述或工具策略声明的风险。高风险操作必须
经过运行时审批。有副作用的操作必须引用达到信任阈值的证据；策略要求时，还必须提供
已注册的补偿工具和补偿意图。无效引用、过期证据、未知工具、错误参数、依赖环、缺失
补偿或证据可信度不足都会在交给运行时前被拒绝。

## 持久化与恢复

规划会话会持久化规范化请求、规划尝试、终态结果、已接受计划版本、准备好的工作流
绑定、模型用量和缓存记录。澄清答案会恢复同一会话并创建新的尝试记录。已接受计划
采用不可变版本。

LangGraph 不负责执行检查点或副作用。工作流准备完成后，第一阶段运行时接管事务状态
转换、幂等键、审批绑定、启动恢复、补偿顺序和脱敏审计事件。该边界将概率性推理与
可靠副作用执行分离。

## 当前边界

- 参考适配器使用本地 SQLite，尚未实现分布式检索和多租户隔离。
- BGE 向量在进程内扫描，适用于本地演示，不适合大型生产语料库。
- 本阶段不包含 Web API、认证服务、用户界面或生产部署清单。
- 参考场景中的工具是确定性模拟实现，生产工具必须提供可信的幂等与恢复探测。
- 规划器一次只提出一个工作流，且只允许一次 Schema 修复。
