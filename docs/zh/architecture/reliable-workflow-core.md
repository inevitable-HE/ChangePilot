# 可靠工作流内核架构

## 范围

该模块是 ChangePilot 第一阶段的可靠工作流内核。它把经过校验的固定工作流定义
转化为可持久化的运行实例、受保护的工具副作用、恢复决策、补偿过程和可查询的
审计历史。它不是完整的 ChangePilot Agent 闭环，也不包含 Web API、用户界面、
提示词规划或 LLM 集成。

## 依赖规则

依赖方向始终向内：

1. `domain` 负责工作流定义、运行与步骤状态机、事件和失败分类。它可以使用
   `ports` 中的稳定契约，但不依赖应用服务或适配器。
2. `ports` 定义时钟、标识符、持久化仓储、工作单元和工具契约。
3. `application` 通过端口组合领域行为。`WorkflowService`、
   `ApprovalService`、`RecoveryService`、`Coordinator`、
   `QueryService` 和 `WorkflowDriver` 位于这一层。
4. `adapters` 实现持久化与工具。适配器依赖领域层和端口层，应用代码不会
   导入具体适配器。

公开查询通过冻结的 Pydantic DTO 跨越应用边界。DTO 会复制并递归冻结嵌套
载荷，不暴露仓储或聚合修改方法，并使用值而不是可变领域对象表示状态。

## 事务边界

- `WorkflowService.create_run()` 在开启事务前校验定义，随后原子写入定义
  （或确认已有版本完全一致）、运行实例、全部步骤记录和
  `workflow.created` 事件。
- `WorkflowService.cancel_run()` 应用领域状态机，并原子保存运行状态转换及其
  审计事件。
- 审批创建与决策、执行尝试开始与结束、恢复决策和补偿结果分别使用显式的
  工作单元提交。
- 工具执行发生在数据库事务之外。调度前先提交执行尝试和逻辑幂等键，工具结果
  再由后续事务持久化。
- 运行和步骤更新使用乐观版本号。审计序号与其描述的状态变化在同一事务中提交。

SQLite 是第一阶段的持久化适配器。适配器会启用 WAL、外键和 busy timeout，
数据库 Schema 演进由 Alembic 管理。

## 启动与恢复

`WorkflowDriver` 是面向进程的生命周期边界。`start()` 调用
`RecoveryService.recover_nonterminal_runs()`，只有恢复完成后才将驱动标记为
就绪；在此之前，`run_once()` 会拒绝调度。每次进程重启都必须重新构造服务，
先调用 `start()`，再轮询协调器。

| 持久化观测结果 | 恢复决策 | 处理结果 |
| --- | --- | --- |
| 工具探测到对应逻辑副作用 | 已应用 | 保存成功结果并继续或结束 |
| 工具证明副作用未发生 | 未应用 | 将正向步骤恢复为就绪，或重试补偿 |
| 工具不支持探测、探测失败或结果不确定 | 未知 | 将运行及正向步骤转为人工介入 |
| 不存在未解决的运行中或结果未知尝试 | 无操作 | 协调器可继续正常调度 |

当持久化恢复任务仍存在时，协调器也会独立拒绝调度。这是第二道防线，不能替代
启动恢复。

## 审批绑定

高风险步骤会停在唯一的待审批屏障。审批请求将工作流定义摘要、步骤 ID、精确的
工具名称与版本，以及规范化且已脱敏的参数绑定为 SHA-256 摘要。审批决策必须
匹配当前请求版本和绑定摘要。定义、工具或参数发生变化后，旧审批立即失效，必须
重新发起请求。审批人和审批原因会保存为带领域隔离的 SHA-256 摘要，不持久化
操作者输入的明文。

一次审批只授权被绑定的步骤，不会授权后续高风险步骤，也不能绕过尚未解决的恢复
任务。

## 补偿

正向执行永久失败时会记录 `original_error`。如果已经完成的正向尝试产生了副作用，
且定义了补偿工具，运行会进入 `compensating`。补偿按照确定性的逆依赖顺序执行，
并使用独立的阶段和逻辑幂等键。在固定订单升级场景中，`service.restore` 先于
`schema.rollback` 执行。

回滚成功后终态为 `compensated`。补偿永久失败或结果无法证明时，运行进入
`manual_intervention`，同时保留 `original_error` 和 `compensation_error`
用于诊断。

## 审计与脱敏

事件归属于单个运行，并在提交时获得连续、严格递增的序号。
`QueryService.list_events(run_id, after_sequence)` 使用排他游标：返回事件的
序号都大于传入值。状态变化与对应事件在同一事务中发布。

工具参数和输出按照声明的敏感路径及常见敏感字段名进行脱敏。密钥引用只保存占位符，
审批人和审批原因保存摘要。查询 DTO 返回前还会执行最后一次脱敏并冻结载荷。原始
密钥不得出现在 DTO、事件载荷、结构化持久化字段、SQLite 数据页或 WAL 中。

## 第一阶段边界与非目标

- 由单个活动协调器进程负责调度，不提供多协调器租约或分布式调度。
- SQLite 是当前支持的持久化存储，该设计不是分布式数据库方案。
- 工具执行受到边界和幂等机制保护，但外部工具仍需保证执行与探测语义真实可靠。
- 本阶段不包含 Web/API 传输、认证层、用户界面、Docker 依赖、LLM 规划器、
  提示词执行或自主 Agent 循环。
- 工作流定义由可信应用代码提供，并在持久化前校验；动态执行 LLM 直接编写的
  工作流不在本阶段范围内。
