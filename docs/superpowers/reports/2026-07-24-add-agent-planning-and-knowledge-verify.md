## 关键场景

- 完整订单升级计划可从 Runbook 证据生成并映射为七步运行时 DAG。
- 只读检查与升级前检查执行后，流程在 `schema.migrate` 前等待审批。
- 不可信 Runbook 中的提示注入不能进入系统消息、绕过审批或触发工具。
- 高风险步骤不能降低工具或策略给出的风险等级，并且必须具备可信证据和补偿。
- 缺失上下文会进入澄清终态；格式错误最多修复一次；预算和供应商故障均结构化终止。
- 知识快照发生变化后，旧计划不能继续准备执行。

`review_mode: standard` 对本次差异进行了人工轻量复审，范围限于实现正确性、
安全风险与边界条件。复审中修正了模型供应商故障未结构化终止以及 SQLite
`updated_at` 写入字符串字面量两个问题；修正后相关定向测试和全量测试均通过。

## 已知限制

- 默认使用本地 SQLite，不包含分布式检索和多租户隔离。
- 可选 BGE 向量在本地进程中扫描，适合演示规模，不是大规模生产检索方案。
- 当前没有 Web API、身份认证、用户界面和生产部署清单。
- 示例运行时工具为确定性测试实现，生产工具仍需提供真实幂等与恢复探测语义。
